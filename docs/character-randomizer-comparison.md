# Рандомайзер внешности: сравнение с оригиналом (StardewValleyDecompiled)

Сравнение кнопки "кубик" (randomize appearance) в нашем экране создания персонажа
(`CharacterCreationScreen.randomizeAppearance`, `client/screen/character/CharacterCreationScreen.java:700`)
с оригинальным рандомайзером Stardew Valley
(`CharacterCustomization.receiveLeftClick`, `StardewValley.Menus/CharacterCustomization.cs:2167-2432`
в `reference-sources/.StardewValleyDecompiled-main`).

## Главный вывод: привязка к полу персонажа

**Наш рандомайзер НЕ учитывает пол (модель тела) персонажа. Оригинальный — учитывает, причём сильно.**

```java
private void randomizeAppearance() {
    skinIndex = random.nextInt(skinIds.size());
    hairIndex = random.nextInt(hairIds.size());
    shirtIndex = random.nextInt(shirtIds.size());
    pantsIndex = random.nextInt(pantsIds.size());
    accessoryIndex = random.nextInt(accessoryIds.size());
    ...
}
```

Метод ни разу не читает `draft.getModelType()` (CLASSIC/SLIM). Индекс волос, рубашки и
аксессуара выбирается равномерно из общего списка `CosmeticRegistry.*Ids()` — того же списка,
что и при обычном пролистывании стрелками `[←] [→]`. Из-за этого при клике на кубик персонаж
классической (условно "мужской") модели может получить хвост, а персонаж slim-модели — арендуемую
"мужскую" причёску, если наши JSON-каталоги когда-нибудь получат гендерно-специфичные записи —
сейчас `hairs.json`/`shirts.json` в `src/main/resources/assets/stardew/character/` вообще
отсутствуют (см. "Не готово к сравнению" ниже), так что на практике вопрос пока не проявляется,
но как только они появятся — рандомайзер их не отфильтрует по полу.

В оригинале `IsMale` — это первое, что проверяется при рандомизации волос, аксессуара и рубашки:

```csharp
// аксессуар — разные ветки и веса для мужского/женского перса
if (Game1.player.IsMale) { ... } else { ... Game1.player.changeAccessory(Game1.random.Next(6, 19)); ... }

// причёска — разные диапазоны индексов для мужского/женского перса
Game1.player.changeHairStyle(Game1.player.IsMale
    ? (Game1.random.NextBool() ? Game1.random.Next(16) : Game1.random.Next(108, 118))
    : Game1.random.Next(16, 41));

// рубашка — свой чёрный список ID специально для мужского перса
Utility.TryGetRandomExcept(GetValidShirtIds(),
    Game1.player.IsMale ? new HashSet<string> { "1056", "1057", ... } : new HashSet<string>(),
    Game1.random, out shirtSelection);
```

То есть в оригинале списки волос для мужского/женского перса физически не пересекаются
(0-16 и 108-118 против 16-41), а у нас общий линейный список без разделения на пол вообще.

## Остальные отличия (алгоритм рандомизации в целом)

| Аспект | Оригинал (`CharacterCustomization.cs`) | Наш код (`CharacterCreationScreen.java`) |
|---|---|---|
| Пол | Ветвится по `IsMale` для волос/рубашки/аксессуара | Не учитывается вообще |
| Аксессуар | Взвешенный выбор: 33% шанс вообще получить аксессуар, дальше вложенные `NextDouble()` пороги (0.33/0.8/0.1/0.5...) на конкретные ID | Равномерный `nextInt(accessoryIds.size())` по всем ID |
| Цвет кожи | `Next(6)` (обычные тона), с 15% шансом переехать на `Next(24)` (редкие/фэнтезийные тона) | Равномерный `nextInt(skinIds.size())` по всем тонам |
| Цвет волос | Генерируется RGB + серия условных корректировок (затемнение, "прижать" к загару `Utility.getBlendedColor(hairColor, Color.Tan)`, рыжий вариант 33%, тёмная кожа → каштановые тона 50%) | Три независимых случайных HSV-канала (`nextInt(100)` на hue/sat/val), без смысловых правил |
| Цвет глаз | RGB, принудительно затемнённый (`/= 2`), с похожими "не даём синему доминировать" правками | Три независимых случайных HSV-канала, без правил |
| Рубашка | `TryGetRandomExcept` — равномерно по валидным ID, но с чёрным списком специфично для пола | Равномерно по всем ID, без чёрного списка |
| Штаны (цвет) | RGB со случайными правками + **жёсткое переопределение по индексу текущей рубашки** (например, рубашка 50 → розовые штаны) — рандомайзер согласует цвет штанов с уже выбранной рубашкой | HSV независим от выбранной рубашки/штанов-ID |
| Штаны (фасон/ID) | Не рандомизируется в этом методе вовсе | `pantsIndex = random.nextInt(pantsIds.size())` — рандомизируется у нас, но не в оригинале |
| Звук клика | Меняется на 15 разных звуков после первого клика (`timesRandom > 0`), первый клик — всегда `"drumkit6"` | Нет звука вообще |
| Имя/ферма/любимая вещь | Не трогает (это в другом экране в оригинале) | Явно не рандомизируется (комментарий "ТЗ §46") — совпадает по духу |

## Итог

Наш рандомайзер — это равномерный «дай случайный индекс/случайный HSV» по каждому полю
независимо. Оригинальный — это кураторский взвешенный генератор: разные веса на разные
аксессуары/причёски, эксклюзии по полу персонажа, согласование цвета штанов с рубашкой,
затягивание случайных цветов к «приятным» диапазонам (загар, приглушённые тона) и полное
разделение мужских/женских списков причёсок и рубашек. Пол персонажа в оригинале — один из
главных входных параметров рандомайзера; в нашей реализации это поле не используется рандомайзером
вообще.

## Не готово к сравнению

`hairs.json` и `shirts.json` в `src/main/resources/assets/stardew/character/` не найдены на момент
анализа (есть только `skins.json`, `pants.json`, `accessories.json`) — то есть волосы и рубашки,
похоже, ещё не переведены на data-driven `CosmeticRegistry` каталог, либо их файлы лежат не там,
где ожидается. Это стоит перепроверить перед тем как добавлять гендерную фильтрацию в
`randomizeAppearance()`, поскольку разделение по полу потребует расширения схемы JSON
(например, поле `"gender": "male"/"female"/"any"` на манер того, что уже есть в
`CosmeticRegistry.loadCosmetics` для `male`/`female` вариантов текстуры).
