# Порядок texture/mask у рубашки + маска зависит от штанов

Черновик для проверки перед кодом (см. чат) — фиксирую, как понял задачу, чтобы сверить перед реализацией.

## Что сейчас (текущий код, `SkinComposer.applyCosmetic`)

```java
if (definition.supportsColor() && variant.mask() != null) {
    applied |= applyTintMask(image, variant.mask(), rgbColor, allowedMask); // 1. маска (крашеная)
}
if (variant.texture() != null) {
    applied |= applyOverlay(image, variant.texture(), allowedMask);        // 2. texture поверх неё
}
```

Порядок: **маска → texture поверх неё**. Всегда, безусловно, для любой категории (рубашка/штаны/волосы/аксессуары).

## Что должно быть (по вашим словам)

1. Порядок нужно перевернуть: **texture → маска поверх неё**. Ассеты изначально рисовались под этот порядок.
2. Для рубашки конкретно (`shirts.json`, там где есть и `texture`, и `mask` — сейчас это `shirt_006/007/009`):
   - `texture` (`base_male/female.png`) — это САМА рубашка (обычная футболка/рубашка), рисуется всегда, когда `shirtId != "none"`.
   - `mask` (`mask_male/female.png`) — это НЕ перекрашиваемая ткань самой рубашки, а **оверлей комбинезона** (лямки/нагрудник), который красится в цвет штанов (`profile.getPantsColor()`, как и сейчас).
3. Маска-комбинезон рисуется **только если у игрока реально есть штаны** (`pantsId != "none"`) — комбинезон без штанов не имеет смысла (нечего "продолжать" вверх).
4. Если `pantsId == "none"` — просто НЕ рисуем маску вообще, остаётся голая texture-рубашка (без лямок).
5. Если `shirtId == "none"` (рубашки вообще нет) — ничего из этого не применяется, рисуется `no_clothes/shirt_male.png` / `shirt_female.png`, как уже сделано. Штаны на это никак не влияют.

## Что это значит на практике

|                              | pantsId = реальные штаны | pantsId = "none" |
|------------------------------|--------------------------|-------------------|
| shirtId = реальная рубашка   | texture + маска-комбинезон (в цвет штанов) поверх | только texture, без маски |
| shirtId = "none"              | `no_clothes/shirt_*` (без изменений) | `no_clothes/shirt_*` (без изменений) |

## Где менять

1. **`applyCosmetic`** (общий для рубашки/штанов/волос/аксессуаров) — поменять местами два блока (texture, потом маска). Проверил остальные категории на побочный эффект:
   - Штаны: `texture` там всегда `character/skin/blank.png` (прозрачная заглушка) — порядок для них визуально не важен, ничего не сломается.
   - Волосы: в `hairs.json` вообще нет `texture`, только `mask` — порядка нет как такового, тоже не сломается.
   - Аксессуары: пока не используются в рендере вообще (см. `SkinComposer` — "v1 визуально не отрисовываются").

   Итог: перевернуть порядок в `applyCosmetic` безопасно для ВСЕХ категорий, а не только рубашки — реального конфликта нет ни у одной из них сейчас.

2. **Условный показ маски-комбинезона (только рубашка)** — это НЕ общая логика `applyCosmetic` (та не знает про `pantsId` вообще, это её не касается для штанов/волос/аксессуаров). Придётся либо:
   - добавить `applyCosmetic` необязательный параметр "рисовать ли маску" (простой `boolean`/явный вызов текстуры и маски раздельно для рубашки), либо
   - в самом `compose()`, в блоке рубашки, разбить единый вызов `applyCosmetic(...)` на два отдельных шага (текстура всегда, маска — только если `!"none".equals(profile.getPantsId())`), не трогая `applyCosmetic` как чёрный ящик для этого конкретного места.

   Второй вариант проще и меньше рискует зацепить остальные категории — предпочтительный.

## Живое обновление

Поскольку `SkinComposer.compose()` уже пересчитывается заново при каждом изменении экипировки (см. `ClothingEquipmentListener` → `RuntimeSkinManager.refreshEquipmentOverride`, реализовано ранее), снятие/надевание штанов в реальной игре автоматически покажет/скроет маску-комбинезон без какого-либо дополнительного кода — это следствие того, что рендер всегда идёт с нуля от текущего `pantsId`.

## Открытые вопросы (для проверки перед кодом)

1. Правило "маска рубашки = комбинезон, гасится без штанов" — это общее правило для **любой** рубашки с маской, или только для конкретных id (например, только `shirt_006/007/009`, у которых сейчас реально есть и texture, и mask)? По факту разницы нет — правило само по себе применяется только там, где у рубашки ЕСТЬ маска, у остальных (texture-only) оно просто не может сработать.
2. Есть ли сценарий, где маска должна остаться видна даже без штанов (например, отдельный флаг в `shirts.json` вроде `"maskRequiresPants": false` для рубашек, где маска — просто обычная перекрашиваемая ткань, а не комбинезон)? Сейчас в доке предполагается, что правило жёсткое и безусловное для всех рубашек с маской.
3. Нужно ли то же самое сделать симметрично для штанов (маска штанов гасится, если нет рубашки)? Из чата это не следует — штаны сейчас без изменений.
